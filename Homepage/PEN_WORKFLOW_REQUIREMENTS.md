# Pen 画布修改要求

## 目的

在 `Homepage/Ark.pen` 中进行任何界面调整时，必须先保证画布结果本身正确，再进入网页实现阶段。

## 强制要求

1. 每次对画布做出可见改动后，必须立即截图验证。
2. 截图验证的对象应优先选择本次修改直接影响的节点；如果影响到整屏观感，还要补一张整屏截图。
3. 对用户最终会直接感知的改动，不能只看局部元素，必须至少补一张整页截图，从真实浏览视角判断效果。
4. 如果截图结果没有达到目标，不能直接结束，必须继续修复后再次截图。
5. 只有在截图确认结果符合预期后，才可以认为这一步修改完成。
6. 如果某种效果在画布或前端中确实难以稳定实现，需要先通过截图说明当前结果，再明确标注“此方案不可继续逼近”。

## 当前执行约定

- 本项目中，涉及 `Ark.pen` 的修改默认遵循“修改 -> 截图 -> 对比 -> 修复 -> 再截图”的循环。
- 对局部问题，优先截图局部节点。
- 对层级、遮罩、裁切、对齐这类问题，截图是必做项，不能只根据节点数据判断完成。
- 对会影响首页观感的调整，局部截图通过后，还要再看一次整页截图。

## 当前案例

- Hero 顶部蓝色媒体占位符：
  - 需要验证它是否被左侧黑色 logo 正确压住。
  - 需要验证它向左延展后，左下角是否还有多余露出部分。
  - 若仍有露出、白边、蓝边、锯齿感过强等问题，必须继续修。
